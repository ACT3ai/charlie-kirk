# Capturing The Tracking Websites

Three jobs no API can do.

**Sites with no public API at all** — the map is the only interface, so a browser is the only client.
**Proving what a page showed on a date**, as a picture rather than a paraphrase. And the one this
investigation needs most: **documenting, carefully, where data that was once public is no longer
retrievable.**

That last one has to be done properly or not at all. The claim "they scrubbed it" is the easiest
thing in the world to say and the easiest thing in the world to disprove, and one bad example
discredits every good one.

## This pass had one specific job, it was run, and it refuted one of our own claims

This pass used to be a general good idea. Then it acquired exactly one question that no other pass
could answer — **and answering it took a claim off this site.**

**Flightradar24 returns HTTP 403 to every scripted request, site-wide.** Tested 24 August 2026
against 13 case tails, **7 unrelated control aircraft**, and Flightradar24's own home page: 403 on all
of them, the same roughly 5,877-byte body every time. It is bot protection. It is not a decision about
any aeroplane, and **it cannot tell a removed record from a present one.** The full control test is on
[the commercial-API page](/Planes/following/apis/proprietary/knowledge).

The consequence was direct. This site recorded the Flightradar24 history for
[N102DZ](/Planes/N102DZ/overview) as **"a real removal, documented"**, on the reasoning that the
Internet Archive holds a populated copy while the live URL 403s today. **The second half of that
reasoning was gone**, and only a browser could see past the block — because a browser is what
Flightradar24 will actually serve.

### The capture, and what it found

Run **24 August 2026**, from a real logged-out browser session, fetching each aircraft same-origin
from inside www.flightradar24.com so the bot check was not in the way.

`captures/fr24_page_availability_2026-08-24.tsv` — **20 aircraft pages: 16 subject tails and 4
unrelated controls. HTTP 200 on every single one**, each with its full identity block.

For N102DZ specifically the live page returns:

| Field | Value |
|---|---|
| Title | `N102DZ - Gulfstream V [555] - Flightradar24` |
| MODE S | `A00C85` |
| Type code | `GLF5` |
| Anything saying removed, blocked, restricted or unavailable | **Nothing** |

Because that conclusion is load-bearing, it was **reproduced by a second, independent session** —
`captures/fr24_n102dz_removal_test_2026-08-24b.tsv`, six probes, HTTP 200 every one. **Both runs
agree.**

**The claim "N102DZ was removed from Flightradar24" is REFUTED. Say refuted, not untested.** No
aircraft page in this investigation has been removed from that site.

### The control is what turned the empty table from a removal into a paywall

N102DZ's flight-history table *is* empty. That is not a deletion — it is the free tier's **seven-day
window**, and the controls prove it in the same session:

| Aircraft | Bytes | History rows | Reading |
|---|---|---|---|
| **N102DZ** (subject) | 53,310 | 0 — "could not find data for specified flight" | Has not flown in seven days |
| **N628TS** (**unrelated control**) | **53,318** | 0 — **the identical message** | Has not flown in seven days |
| N888KG (subject) | 53,338 | 0 — same message | Same state |
| SU-BTT (subject) | 68,606 | 56 | Flew recently |
| SU-BND (subject) | 57,612 | 14 | Flew recently |
| EI-DCL (control, Ryanair) | 238,357 | 683 | Flies daily |

**Every row, subject and control alike, carries the upgrade paywall notice.** The empty table tracks
whether the aircraft flew in the last seven days, and nothing else. **A control aircraft captured in
the same session on the same day is not a nicety here — it is the entire method.** A capture of
N102DZ alone would have proved nothing, whatever it showed, because there would have been nothing to
compare it against.

### What this does NOT settle, and it travels with the refutation everywhere

**A page that loads today cannot testify about what its table held in May 2026.**

* **"The page was taken down" — REFUTED.**
* **"History was specifically purged and later restored" — beyond this method IN EITHER DIRECTION.**
  Not supported, not refuted. **No page on this site may assert it.**
* **A logged-out free tier is the weakest view Flightradar24 offers.** Silver shows 90 days, Gold a
  year, Business three years. **We have not looked through a paid tier**, so every Flightradar24
  observation in this investigation is a free-tier observation and should be read as one.

The honest three lines, for any page that touches this:

1. The Flightradar24 **403 our scripts see is bot protection.** It says nothing about any aircraft.
2. The Flightradar24 **page is present and complete in a browser.** Nothing was taken down.
3. **What it displayed in May 2026 is not reachable by any method we have, and we do not claim it.**

And the general limit still stands for every other capture this pass will ever make: **a page that
was public and is not now is a fact. Why is not something a capture can see.** A redesign, a URL
change, a retention window, a commercial paywall, an owner's lawful blocking request and a deliberate
removal all look identical from outside.

**Do not defeat a paywall to run the paid-tier test.** A subscription honestly bought is a
subscription; a workaround is the first thing a hostile reader uses to discard everything else on
this site.

## What we already know is different

Two changes are confirmed from the [open-source pass](/Planes/following/apis/public_open_source/knowledge),
both checked **24 August 2026**:

* **ADS-B Exchange historical pages return HTTP 403 to the public.** Several of the original
  screenshots behind this whole claim were taken from that site while it was open. The data did not
  disappear — it moved behind a subscription when the site commercialised. **Anyone re-checking an old
  screenshot there today cannot, and may wrongly conclude something was removed.**
* **airplanes.live now returns HTTP 403** and asks you to email a description of your project first.
  It was open before.

Neither is evidence of anything about this case. Both are exactly the kind of thing that gets
mistaken for it.

And one that cuts directly against a scrubbing reading: the free historical archive returns **403 for
every date from 12 October to at least 15 December 2025, for every aircraft we tried — including one
with no connection to this case at all.** That band happens to cover the dates a tracker claims
SU-BTT was photographed at Sharm el-Sheikh. **It is an archive-wide condition, not a suppression, and
reporting it as one would be false.**

**Corrected and extended, 24 August 2026.** A control basket of nine airframes — four from this case,
**five unrelated** — mapped adsb.lol precisely: it serves normally through **11 October 2025**, then
**403 for every aircraft from exactly 12 October 2025 to about 30 December 2025**, then **404 for
every aircraft from about 31 December 2025 to about 1 August 2026**, then normal again from about
**2 August 2026**. The earlier "31 December works" was wrong. A second archive,
`globe.airplanes.live`, serves from about November 2023 to the present **throughout both bands**, so
the Sharm el-Sheikh dates can now be checked after all. **Both bands behave identically for control
aircraft. Neither is about this case and neither may be reported as scrubbing.** The full map is on
[the open-source page](/Planes/following/apis/public_open_source/knowledge).

## What APIs they have — read as: which sites can be captured at all

`apis/browser_capture/code/targets.json` holds **128 targets** — one per (site, aircraft) across
8 sites and 16 aircraft, each with the URL, the ICAO hex, which investigation thread the aircraft
belongs to, and what that site is good for.

| Site | What it is worth capturing for |
|---|---|
| **Flightradar24** | The aircraft-history table the original claims were screenshotted from. Free tier shows a limited window — **record how deep that window goes**, it is part of the finding. |
| **ADS-B Exchange** | Free map only; historical replay is behind the paywall. Capture the paywall itself. |
| **FlightAware** | Aggressive bot protection. If it blocks, **record the block and stop.** |
| **RadarBox** | An independent receiver network — a genuine cross-check, not another view of the same feed. |
| **Planespotters / JetPhotos** | Photographs with dates and places. **A photograph of an airframe at a field on a date is a different kind of evidence from a transponder reading**, and it is not vulnerable to the same failure modes. |
| **adsb.lol globe** | The free map over the same archive the open-source scripts pull as JSON. |
| **airplanes.live globe** | Its API is gated now; record whether the map still is not. |

## How you use them

Driven by Claude Code's browser tools, following `apis/browser_capture/p_get_data.mdx`. There is no
scraper here on purpose — the point is to capture what a human visitor sees, rendered, with its
JavaScript run.

**Every capture needs four things or it does not count:** the screenshot, the page text, the URL and
the **UTC** time of capture, and the HTTP status.

Alongside the screenshot, `monolith` freezes a whole page into one self-contained file that still
renders years later after a redesign:

```
monolith -o captures/<site>/<tail>/<utc>.html "<url>"
```

A screenshot proves what was displayed. Monolith preserves what was underneath. Use both.

### Rules that are not negotiable

* **Never log in, never defeat a paywall, never click through a terms gate, never create an account.**
  A page that requires it is a finding, not an obstacle.
* **Never trigger a JavaScript alert, confirm or prompt.** A modal blocks every further browser
  command and the session has to be rescued by hand.
* Images go to the repo and are embedded by **local repo path**, never by an IPFS gateway URL. Images
  are tracked in git — an untracked image renders locally and 404s for every real visitor.
* Check the ban list before embedding anything.

## The comparison is the finding

A capture alone says "this is what the page shows today". Paired with the Internet Archive snapshot
nearest the claim date — `wayback.js` in the open-source pass, which reads the CDX API and reports
snapshot counts, dates, HTTP statuses and content digests — it can say **"this is what the page showed
then, and this is what it shows now."**

Two things must never be blurred:

* **NEVER SHOWED IT** — no evidence the page ever carried this. **That is not scrubbing.** It is the
  absence of a claim ever having been supported.
* **SHOWED IT AND NO LONGER DOES** — a documented change in the public record, with dates on both ends.

## And it still cannot tell you why

**A redesign, a URL change, a retention window rolling over, a commercial paywall and a deliberate
removal all look identical from outside.** Nothing in this pass distinguishes them.

So every page built from these captures states which of those it can and cannot rule out. A page
that alleges scrubbing without ruling out a redesign will be taken apart by the first person who
checks — and it deserves to be.

## What we got so far

**One site captured, out of eight. Flightradar24, twice, on 24 August 2026.**

| Capture | What it covers | Result |
|---|---|---|
| `captures/fr24_page_availability_2026-08-24.tsv` | 16 subject tails + 4 unrelated controls | **HTTP 200 on all 20.** Full identity blocks. Nothing removed. |
| `captures/fr24_n102dz_removal_test_2026-08-24b.tsv` | Independent re-test, 6 probes, different operator | **HTTP 200 on all 6.** Reproduces the first run. |

**That is 1 site of 8** — all 16 Flightradar24 targets, plus 4 control aircraft that are not in
`targets.json` at all and were added precisely because a capture without a control proves nothing.
ADS-B Exchange, FlightAware, RadarBox, Planespotters, JetPhotos, the adsb.lol globe and the
airplanes.live globe have not been captured at all: **112 of the 128 targets are untouched.**

The Internet Archive half of the job has also been run, and it produced the most uncomfortable finding
on this page.

### Nobody archived the evidence

30 target URLs checked against the Internet Archive CDX API on **24 August 2026** — the tracking-site
pages for the five Egyptian tails and T7-ELL across Flightradar24, ADS-B Exchange, FlightAware,
RadarBox and Planespotters.

**22 of the 30 have zero snapshots.** Including both of these:

> and three of its zeros were failed queries" below. **SU-BTT's ADS-B Exchange page has 3 snapshots,
> not 0.** The Flightradar24 row is unchanged and still reads zero.

| Page | Snapshots | Range |
|---|---|---|
| **Flightradar24 — SU-BTT** | **0** | **never captured** |
| ~~**ADS-B Exchange — SU-BTT**~~ **corrected → 3** | ~~0~~ **3** | ~~never captured~~ **1 Sep – 17 Dec 2022** |
| Flightradar24 — SU-BND | 2 | Oct 2025 – Nov 2025 |
| Flightradar24 — SU-BTU | 1 | Aug 2022 |
| Flightradar24 — SU-BGM | 1 | May 2020 |
| Flightradar24 — SU-BTV, T7-ELL | 0 | never captured |
| ADS-B Exchange — SU-BTU / SU-BTV / T7-ELL | 3 each | 2022 – 2023 |
| ADS-B Exchange — SU-BND / SU-BGM | 2 / 1 | 2022 |
| FlightAware — all five | 0 | never captured |
| RadarBox — all five | 0 | never captured |
| Planespotters — all five | 0 | never captured |

**SU-BTT is the lead aircraft of the entire following claim, and neither its Flightradar24
aircraft-history page nor its ADS-B Exchange page was ever archived** — while all four of the other
Egyptian tails have at least one snapshot of one or the other. Not before the claim, not during it,
not after.

**Corrected.** SU-BTT's **ADS-B Exchange** page **was** archived — 3 snapshots, 1 September to
17 December 2022. What survives is the narrower and still-uncomfortable version: **SU-BTT has zero
archived snapshots on Flightradar24, FlightAware, RadarBox and Planespotters**, and its three ADS-B
Exchange snapshots all predate the claim by three years. The aircraft the case turns on is still the
one with almost no page archive — but the sentence above overstated it, and the overstatement was
caused by our own failed query.

The two SU-BND snapshots that do exist are both dated **after** the October 2025 broadcast that
launched the claim. They record the reaction, not the evidence.

Every ADS-B Exchange snapshot predates the claim by two to three years, so none of them shows what a
tracker was looking at in autumn 2025 either.

### The sweep was re-run, and three of its zeros were failed queries

Two things were wrong with the first sweep, and both were ours.

**One — the query threw away the evidence it was looking for.** It used `collapse=digest`, which
returns only **distinct-content** captures. Every count it produced was a **floor, not a total**, and
the test the sweep exists to run — *did this page stop changing?* — was **impossible by
construction**, because collapsing on digest discards exactly the repeated captures that test needs.

**Two — three queries failed with HTTP 504 and were written into the report as `"snapshots": 0`.** A
timeout was recorded as an absence. One of the three was `globe.adsbexchange.com/?icao=0101d3` —
**SU-BTT**.

The re-run drops the collapse, adds retries, and **reports a failed query as `UNKNOWN` rather than as
zero.** **30 of 30 queries succeeded, 0 failed.**

| | |
|---|---|
| Total snapshots | 19, across 9 URLs |
| Genuinely never archived | **21 URLs** — query succeeded, result empty |
| HTTP status of every CDX row on every URL | **200** |
| **200 → 404 transitions anywhere in the dataset** | **None** |

**There is no 200→404 transition anywhere in this data.** Any page on this site claiming one is wrong.

**And the ADS-B Exchange snapshots that do exist are empty JavaScript shells.** Digest
`AJQHJML54QE6X2IE4TMCM24E3DPGKFD6` is byte-identical across **SU-BGM, SU-BTV and SU-BTU**;
`U743ARQOTM724WNPQLSMSX7TSTHW3FYE` across **SU-BND and T7-ELL**. Identical bytes for different ICAO
hex codes can only mean the Archive captured the application frame, not the aircraft data. **Those
snapshots carry no per-aircraft evidence and must not be cited as if they did** — which means the
"3 snapshots" correction above restores a count, not an item of evidence.

**Twenty-one URLs nobody ever asked the Archive to crawl is not suppression.** It is the ordinary
state of almost every page on the internet.

**What this means, stated carefully.** It does not mean anything was removed. It means that for the
aircraft at the centre of this case **there is currently no independent record of what the tracking
sites displayed at the time the claims were made** — so "the page changed" cannot be tested, in
either direction, for the tail that matters most.

**And one caveat that must travel with the table.** The CDX API matches exact URL strings. A page
archived under a slightly different URL form would not appear here. "Zero snapshots for this URL" is
not the same as "never archived anywhere", and this table should be re-run against URL variants
before anybody leans on it.

Raw responses: `apis/public_open_source/data/wayback/`.

## What we did NOT get

* **What any Flightradar24 page displayed on a past date.** The removal claim is refuted; the
  narrower purge-and-restore question is **beyond this method in either direction**, and no page on
  this site may assert it.
* **The paid-tier Flightradar24 view.** Every observation we hold is from a **logged-out free tier**
  — 7 days, against 90 days on Silver, a year on Gold, three years on Business. Nobody has looked
  through a paid account, us included.
* **No screenshot or `monolith` freeze accompanies the two Flightradar24 captures.** They are
  tab-separated readings of the rendered pages. **A capture is supposed to carry the picture as well**
  — that is a gap in our own method, not in the finding.
* **Seven of the eight target sites, uncaptured.** 112 of 128 targets untouched: ADS-B Exchange,
  FlightAware, RadarBox, Planespotters, JetPhotos, the adsb.lol globe, the airplanes.live globe.
* **No URL-variant sweep.** The zero-snapshot result above needs re-running against trailing slashes,
  alternate paths and the sites' older URL schemes before it is quotable.
* **No copy of the original screenshots** the claims were read off, with their own provenance —
  which post, which date, which account. Given that the Archive holds nothing usable for SU-BTT —
  zero on four sites, and three empty JavaScript shells on the fifth — **those screenshots may now be
  the only record of what the page showed**, which makes collecting them with their provenance the
  single most urgent task on this page.
* **No record of which tracked tails, if any, appear on a vendor blocking list.**
* **No capture of the sites that are now closed** — the ADS-B Exchange historical pages and the
  airplanes.live API — as they appear today, showing the paywall and the gate. Those are quick and
  should be done first.

## Where this page fits

This pass drives a real browser at the tracking sites, and its job inside [the data-collection section](/Planes/following/apis/overview) is the one no API can do — proving what a page showed on a date — which is how it produced [the correction that a 403 is not a deletion](/Planes/Flight-Data-Recovery/What-A-403-Means), took a claim off this site, and forced the rewrite of [the commercial-API page](/Planes/following/apis/proprietary/knowledge). That correction matters well beyond aircraft, because "they scrubbed it" is asserted across the case — [about search-trends data](/Censorship/Google_Search_Trends_Scrubbing), [about witness video](/CoverUp/Videos_Deleted_Remotely), [about removed podcast episodes](/TPUSA/apple-podcasts-removed-charlie) — and one bad example discredits every good one. Read [the flight-data recovery hub](/Planes/Flight-Data-Recovery/overview) next for what the browser work was checked against: five unrelated control aircraft failed identically on the same endpoint, which is the test that separates a retention boundary from a removal, and the archived copy of [the N102DZ page](/Planes/N102DZ/overview) still preserved a seven-day window that has since rolled past.
